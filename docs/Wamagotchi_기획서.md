## 1. 프로젝트 개요

### 1.1 한 줄 소개

> **"당신이 쓰는 모든 글자가 정령의 밥이자 모험의 원동력이 된다."**

사용자가 앱 안의 메모장에 일기·업무 메모·아이디어를 타이핑하면, 그 글자 수와 작업 패턴이
가상의 펫(정령)의 먹이와 경험치로 변환된다. 사용자가 일에 집중할수록 정령은 강해지고,
스스로 던전을 탐험하며 전리품을 모아 텍스트 로그로 보고한다.

### 1.2 이름의 의미

- **Wamagotchi = Writing(쓰기) + Tamagotchi(다마고치)**
- 한글 표기: **와마고치**
- **정령의 이름은 유저가 부화 시 자유롭게 입력해 결정한다.** (개명 아이템으로 이후 변경도 가능 — 상세 규칙은 게임 시스템 기획서 1.1 참조)
- 이 문서의 예시에서는 정령 이름으로 **"에코(Echo)"**(사용자가 쓴 글의 메아리라는 의미)를 사용한다.

### 1.3 핵심 가치 제안 (Why this app?)

1. **생산성 = 플레이**: 게임을 하려고 시간을 내는 것이 아니라, 어차피 하던 기록/작업이 곧 게임 진행이 된다.
2. **죄책감 없는 게임**: 많이 플레이할수록(=많이 쓸수록) 현실의 결과물이 쌓인다.
3. **레트로 감성**: 1990년대 다마고치와 고전 로그라이크의 아날로그 감성을 텍스트 중심 UI로 재현한다.
4. **가벼움**: 서버 없이 완전 오프라인으로 동작하는 초경량 앱.

### 1.4 타깃 유저

- 메모·일기·글쓰기 습관을 만들고 싶은 사람
- 방치형 게임과 다마고치식 교감을 좋아하는 라이트 게이머
- 레트로 픽셀 감성(게임보이, LCD 전자게임기)에 향수가 있는 20~40대

## 2. 콘셉트의 기원과 모바일 전환

### 2.1 원형 아이디어 (PC 버전: `내_정령.txt`)

최초 기획은 PC용이었다. 백그라운드 프로그램이 사용자의 문서 저장(Ctrl+S) 이벤트를 감지해,
바탕화면의 `내_정령.txt` 파일 내용을 덮어쓰며 펫을 성장시키는 구조.
게임의 모든 화면과 조작(상점 구매 등)이 텍스트 파일 하나 안에서 이루어지는 것이 핵심 감성이었다.

```text
[ 0_0 ] -> 이름: 에코 (Lv.15 그림자 도적)
상태: 활기참 (포만감 85%) / 속성: 심야형
보유 마나(재화): 4,200 M
--------------------------------------------------
[최근 모험 로그]
- 오전 10:30 | 당신이 기획서를 500자 쓰는 동안, 에코가 '휴지통 던전' 2층을 돌파했습니다!
- 오전 10:45 | 고블린을 처치하고 [빛나는 키캡]을 획득했습니다. (마나 +500)
```

### 2.2 모바일 전환 시 제약과 해결책 (매우 중요)

Android/iOS는 보안상 **앱이 백그라운드에서 다른 앱의 타이핑을 감지하거나 파일을 읽는 것을 엄격히 차단**한다.

- **해결책: 앱 자체를 '메모장 + 게임'이 결합된 형태로 만든다.**
- 사용자는 Wamagotchi 앱 안의 텍스트 에디터로 메모/일기/업무를 작성한다.
- 앱 내부 입력이므로 글자 수 계산, 키워드 감지, 자동 저장이 완벽하고 매끄럽게 동작한다.
- PC 원안의 "텍스트 파일 하나가 곧 게임 화면"이라는 감성은, 앱 상단의 **텍스트 스타일 상태창**으로 계승한다.

### 2.3 디자인 필러 (Design Pillars)

| # | 필러 | 설명 |
|---|---|---|
| 1 | 기록이 곧 먹이 | 별도의 게임 조작을 요구하지 않는다. 일상적인 글쓰기가 컨트롤러다. |
| 2 | 아날로그 레트로 | 1-bit/8-bit 픽셀, LCD 팔레트, 각진 테두리, 텍스트 로그 중심. |
| 3 | 창발적 성장 | 유저의 실제 작업 패턴(시간대·글 길이·키워드)이 펫의 클래스와 운명을 바꾼다. |
| 4 | 무한한 방치 플레이 | 환생(Prestige)과 세대교체로 끝없이 이어지는 성장 루프. |

## 3. 핵심 게임 루프 (Core Gameplay Loop)

```
┌────────────────────────────────────────────────────────┐
│  ① 입력    사용자가 에디터에 메모/일기/업무를 타이핑         │
│     ↓                                                  │
│  ② 변환    저장 시 늘어난 글자 수 → 마나(Mana) + 경험치(Exp) │
│     ↓                                                  │
│  ③ 성장    레벨업 → 외형 진화 / 작업 패턴에 따른 클래스 분기  │
│     ↓                                                  │
│  ④ 모험    포만감 50% 이상이면 백그라운드 던전 자동 탐험      │
│     ↓                                                  │
│  ⑤ 보상    전리품·마나 획득 → 상점 구매·장비 강화 → 다시 ①   │
└────────────────────────────────────────────────────────┘
```

- **단기 루프(분 단위)**: 타이핑 → 저장 → 마나/경험치 상승 → 로그 확인.
- **중기 루프(일 단위)**: 포만감 유지 → 던전 층 돌파 → 아이템 수집 → 장비 교체.
- **장기 루프(주/월 단위)**: 클래스 진화 → 최대 레벨 도달 → 환생 → 영구 버프 + 새로운 종족/던전.

## 4. 화면 구성 및 UI/UX

### 4.1 메인 화면: 스플릿 뷰

전체 화면을 2개의 주요 영역으로 분할한다. (세로 모드: 상/하, 가로·태블릿·PC: 좌/우)

#### 🅰️ 상단 — 에코 상태창 (게임 영역)

옛날 다마고치·게임보이 화면처럼 굵은 실선 테두리로 감싸진 영역.

```text
┌──────────────────────────────────────┐
│   [ 0_0 ]    에코  Lv.15 그림자 도적    │
│                                      │
│   포만감  ▓▓▓▓▓▓▓▓░░  85%  (활기참)    │
│   경험치  ▓▓▓▓▓░░░░░  52%             │
│   마나    4,200 M      속성: 심야형     │
├──────────────────────────────────────┤
│ > 에코가 '휴지통 던전' 2층을 돌파했다!     │
│ > 오타 슬라임 처치! [빛나는 키캡] 획득     │
└──────────────────────────────────────┘
```

- 중앙에 Higgsfield로 생성한 픽셀 아트 펫이 **대기(idle) 애니메이션**으로 재생.
- 텍스트 정보: 이름/레벨/클래스, 경험치·포만감 상태바, 보유 마나, 속성.
  (이름은 유저가 부화 시 직접 입력한 이름으로 표시 — 목업의 '에코'는 예시)
- 하단 로그창: 최근 모험 로그 2~3줄 자동 스크롤. 탭하면 전체 로그 화면으로 이동.
- 상태창 탭 시 펫이 짧은 반응 모션(점프, 하트 등)을 보여주는 교감 요소 포함.

#### 🅱️ 하단 — 텍스트 에디터 (생산성 영역)

- 사용자가 실제로 글을 쓰는 깔끔한 메모장 공간.
- 구성: 제목 입력칸 + 본문 입력칸 + 하단 플로팅 **저장(SAVE)** 버튼.
- 저장 버튼을 누르는 순간이 게임의 핵심 트리거(글자 수 정산)다. — 다마고치에게 밥을 주는 행위.
- 게임 요소가 메모 작성을 방해하지 않도록 직관적이고 심플하게 유지한다.

### 4.2 화면 흐름도

```
[메인 화면 (상태창 + 에디터)]
 ├─ 메모 목록      : 작성한 메모 열람/검색/삭제 (제목·날짜·글자 수 표시)
 ├─ 모험 로그      : 전체 탐험/전투/획득 기록 타임라인
 ├─ 인벤토리 & 장비 : 보유 아이템 확인, 무기/방어구 장착, 포션 사용
 ├─ 상점          : 마나로 아이템 구매 (Phase 4)
 ├─ 명예의 전당    : 은퇴(환생)한 역대 정령의 기록 (Phase 5)
 └─ 설정          : 알림, 폰트 크기, 데이터 백업/초기화
```

### 4.3 UX 원칙

- **글쓰기 우선**: 앱 실행 → 즉시 에디터에 커서. 게임 확인은 시선 이동만으로 충분해야 한다.
- **강요 없는 게임**: 팝업·강제 튜토리얼 최소화. 게임을 무시하고 메모장으로만 써도 불편함이 없어야 한다.
- **로그가 곧 연출**: 화려한 이펙트 대신, 잘 쓰인 한 줄의 텍스트 로그가 보상의 쾌감을 전달한다.

## 5. 게임 시스템 상세

> ⚖️ 아래의 모든 수치는 **초기 밸런스 제안값**이며, 플레이테스트를 통해 조정한다.
>
> 📎 이 장은 시스템의 뼈대 요약이다. 종족·성격·스킬·퀘스트·도감·감정 날씨 등
> **확장된 상세 설계와 최신 밸런스 수치는 [게임 시스템 기획서](Wamagotchi_게임시스템_기획서.md)가 우선**한다.

### 5.1 재화·경험치·레벨

| 요소 | 규칙 (제안값) |
|---|---|
| 마나 (Mana, M) | 저장 시 **새로 늘어난 글자 1자당 +1 M**. 게임 내 화폐. |
| 경험치 (Exp) | 저장 시 **늘어난 글자 1자당 +1 Exp**. |
| 레벨업 요구 Exp | `100 × 현재 레벨` (Lv.1→2: 100, Lv.2→3: 200 …) |
| 최대 레벨 | **Lv.100** (도달 시 '은퇴' 가능 → 5.7 환생 참조) |
| 레벨업 연출 | 로그창에 `"에코가 Lv.16으로 성장했다!"` 출력 + 픽셀 반짝임 효과 |

- 글자 수 기준은 공백 제외 문자 수. **삭제된 글자는 차감하지 않는다** (글을 다듬는 행위에 벌점 없음).
- 진화(외형 변경) 구간: **Lv.1 알 → Lv.5 부화(꼬마 정령) → Lv.15 1차 진화 → Lv.30 2차 진화(클래스 확정) → Lv.60 최종 형태**.

### 5.2 포만감 (Hunger) 시스템

다마고치 교감의 핵심. "밥을 챙겨줘야 한다"는 감각을 타이핑으로 구현한다.

| 규칙 | 값 (제안) |
|---|---|
| 회복 | 저장한 글자 100자당 포만감 +5%p (최대 100%) |
| 자연 감소 | 시간당 -4%p (약 25시간이면 100% → 0%) |
| 탐험 조건 | 포만감 **50% 이상**일 때만 던전 자동 탐험 진행 |
| 저포만 상태 | 50% 미만: 탐험 중단, 펫이 배고픈 표정으로 변경 |
| 0% 상태 | 사망하지 않음. '기절(시무룩)' 상태로 성장 정지. 글을 쓰면 즉시 회복 시작 |

> 의도적으로 **죽음 시스템은 넣지 않는다.** 벌은 "탐험 정지"까지만. 생산성 앱에서
> 죄책감·스트레스는 이탈 요인이기 때문이다. 대신 오래 방치 후 복귀하면
> `"에코가 당신을 기다리고 있었다..."` 같은 재회 이벤트로 복귀를 환영한다.

### 5.3 작업 패턴 진화 시스템 (창발성 ①)

사용자의 **실제 작업 습관**이 펫의 클래스와 스탯을 결정한다. 같은 앱을 써도 유저마다 전혀 다른 정령이 자란다.

| 작업 패턴 | 판정 기준 (최근 30회 저장 통계) | 진화 클래스 | 특화 스탯 |
|---|---|---|---|
| 심야형 | 22:00~02:00 저장 비중 40% 이상 | **그림자 도적** (어둠 속성) | 치명타율 ↑ |
| 단문·잦은 저장형 | 평균 저장 글자 수 300자 미만 & 일 저장 5회 이상 | **암살자** | 민첩(탐험 속도) ↑ |
| 장문·묵직한 저장형 | 1회 저장 2,000자 이상 비중 30% 이상 | **기사** | 체력·방어력 ↑ |
| 균형형 | 위 조건 미충족 | **모험가** (기본) | 전 스탯 균등 |

- 클래스 분기는 **Lv.30 2차 진화 시점**에 최근 통계로 확정된다. (이후 환생 시 재분기 가능)
- 속성(심야형/아침형 등)은 상태창에 표기되어 "이 정령은 내 생활 패턴의 거울"이라는 서사를 만든다.

**스탯 정의**

| 스탯 | 효과 |
|---|---|
| 공격력 (ATK) | 전투 승리 확률·처치 속도 가중치 |
| 방어력 (DEF) | 전투 패배 시 손실(탐험 후퇴 층수) 감소 |
| 체력 (HP) | 연속 전투 지속력, 탐험 1회당 진행 가능 층수 |
| 민첩 (AGI) | 탐험 틱당 이동 속도, 회피 |
| 치명타율 (CRIT) | 희귀 아이템 드롭률·보너스 마나 확률 |

### 5.4 특수 키워드 감지 (창발성 ②)

저장 시 **새로 추가된 텍스트**에서 특정 단어를 감지하면 이벤트가 발동한다.
사용자의 일상 언어가 게임 세계에 메아리(Echo)로 울려 퍼지는 시스템.

| 키워드 (예시) | 이벤트 | 효과 (제안) |
|---|---|---|
| 완료, 해냈다, 성공 | 버프 [성취의 기운] | 1시간 동안 마나 획득 +20% |
| 스트레스, 힘들다 | 희귀 아이템 [스트레스 결정체] 드롭 | 상점에 고가(+800 M)로 판매 가능 — "고생이 보상이 된다" |
| 오류, 버그 | 특수 몬스터 '버그 벌레' 출현 | 처치 시 보너스 마나 +300 |
| 감사, 사랑 | 펫 기분 상승 | 포만감 +10%p |
| 마감, 급함 | 버프 [질주 본능] | 30분간 탐험 속도 2배 |

- **발동 상한**: 키워드당 1일 3회 (도배 어뷰징 방지).
- 키워드 사전은 데이터 파일로 분리해 업데이트로 쉽게 추가할 수 있게 설계한다.

### 5.5 방치형 던전 탐험 & 자동 전투

- 포만감 50% 이상이면 정령이 **자동으로 던전을 등반**한다. 유저 조작 불필요.
- 전투는 실시간 시뮬레이션이 아니라, **주기적 '틱'마다 스탯 가중 확률 테이블로 결과를 생성**해
  텍스트 로그로만 출력한다. (고전 로그라이크의 메시지 로그 감성)
- **틱 주기**: 앱 사용 중 5분당 1틱. **오프라인 정산**: 앱 재실행 시 경과 시간만큼 로그 일괄 생성 (최대 8시간분).

**던전 목록 (PC 폴클로어 세계관)**

| 던전 | 개방 조건 | 대표 몬스터 |
|---|---|---|
| 휴지통 던전 | 기본 개방 | 오타 슬라임, 구겨진 종이 골렘, 고블린 |
| 캐시 파일의 늪 | Lv.20 | 팝업 고블린, 광고 배트 |
| 스팸 메일의 탑 | Lv.50 | 피싱 하피, 404 유령 |
| C드라이브의 심연 | 환생 1회 | 단축키 미믹, 커널 나이트 |
| 블루스크린의 계곡 | 환생 3회 | 블루스크린 드래곤 (최종 보스) |

**로그 예시**


### 5.7 환생(Prestige) & 세대교체 — 엔드 콘텐츠

무한한 플레이를 보장하는 장기 루프.

1. **은퇴**: 정령이 Lv.100에 도달하면 '은퇴'시킬 수 있다.
2. **명예의 전당**: 은퇴한 정령은 '명예의 전당' 화면에 훈장처럼 영구 기록된다.
   (이름, 클래스, 함께 쓴 총 글자 수, 최고 도달 던전 — PC 원안의 `명예의전당.txt` 계승)
3. **영구 계정 버프**: 첫 환생 시 **글자당 마나 획득 1.5배**, 이후 환생마다 +0.25배씩 누적.
4. **세대교체**: 완전히 다른 종족의 알(불꽃/물/기계 정령 등)을 새로 부화시켜 Lv.1부터 재시작.
5. **심층 던전 개방**: 환생 횟수에 따라 'C드라이브의 심연', '블루스크린의 계곡' 등
   더 깊고 어려운 던전이 열린다.

> **에코(정령) 알 단계 (Lv.1)**
> `1-bit pixel art, pure black and white, retro tamagotchi style, a mysterious egg with cracks, extremely simple UI element, solid white background`

> **에코(정령) 기본 형태 (Lv.5)**
> `1-bit pixel art, pure black and white, retro tamagotchi style, a cute little shadow ghost monster, front view, extremely simple UI element, solid white background`

> **던전의 몬스터 (로그라이크 감성)**
> `8-bit pixel art, retro roguelike style, simple slime monster sprite, top-down view, limited color palette, solid white background`

## 7. 기술 설계

### 7.1 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | **Flutter** (대안: React Native) | 코드 한 벌로 Android/iOS/PC 대응. AI 학습 데이터가 풍부해 코드 생성 품질이 높음 |
| 상태 관리 | Riverpod 또는 Provider (Claude 추천안 채택) | 대중적이고 유지보수 용이 |
| 로컬 저장소 | 게임 상태: `shared_preferences` / 메모·로그: `Hive` 또는 `sqflite` | 서버 없이 오프라인 완결 |
| 아키텍처 | **MVVM (관심사 분리)** | UI/로직/데이터 계층 분리로 향후 기능 추가 용이 |
| 코딩 도구 | Claude (Cursor 등 AI 에디터 병용) | — |

### 7.2 아키텍처 원칙

- UI(화면), Logic(계산식·게임 규칙), Data(저장소)를 **각각 다른 폴더와 파일로 분리**한다.
  한 파일에 뒤섞인 '스파게티 코드'는 유지보수 불가 → 초기 설계 단계에서 구조부터 잡는다.
- 밸런스 수치(마나 환산율, 레벨 곡선, 드롭 테이블, 키워드 사전)는 **상수/데이터 파일로 분리**해
  코드 수정 없이 튜닝할 수 있게 한다.

**폴더 구조 (예시)**

```
lib/
 ├─ main.dart
 ├─ models/        # Memo, PetState, Item, AdventureLog, HallOfFameEntry
 ├─ viewmodels/    # 게임 규칙·계산식 (경험치, 포만감, 탐험 틱, 키워드 감지)
 ├─ views/         # 메인(상태창+에디터), 메모 목록, 인벤토리, 상점, 명예의 전당
 ├─ services/      # 로컬 저장소 입출력, 오프라인 정산
 └─ data/          # 밸런스 상수, 아이템/몬스터/키워드 테이블
```

### 7.3 데이터 모델 (저장 항목)

| 모델 | 필드 (요약) |
|---|---|
| Memo | id, 제목, 본문, 생성/수정일, 글자 수 |
| PetState | 이름, 레벨, Exp, 마나, 포만감, 클래스, 속성, 스탯, 현재 던전/층 |
| InventoryItem | 아이템 id, 수량, 장착 여부 |
| AdventureLog | 시각, 로그 텍스트, 유형(전투/획득/이벤트) |
| HallOfFameEntry | 세대, 이름, 클래스, 총 글자 수, 최고 던전, 은퇴일 |
| SaveStats | 최근 저장 30회 통계 (시각, 글자 수) — 진화 분기 판정용 |

- 모든 데이터는 기기 내부에 저장하며 **오프라인에서 완전 동작**한다. (서버/백엔드 없음)
- 설정 화면에 로컬 백업(내보내기/가져오기) 기능을 제공해 기기 교체에 대비한다.

## 9. AI 협업 워크플로 (제작 프로세스)

한 번에 전부 만들어 달라고 요청하면 코드가 엉킨다. 아래 6단계 순서로 Claude/Higgsfield에 나눠 요청한다.

### 1단계 — 프로젝트 아키텍처 설계 (Claude)

> "나는 Flutter로 'Wamagotchi'라는 방치형 생산성 앱을 만들 거야. 코딩을 모르니 네가 전담 엔지니어가
> 되어 줘. 이 기획서를 읽고, 향후 기능 추가가 쉽도록 MVVM 패턴(관심사 분리)을 적용하고, 상태 관리
> 라이브러리는 가장 대중적이고 유지보수하기 좋은 것으로 추천해서 프로젝트 폴더 구조를 먼저 설계해 줘."

### 2단계 — 텍스트 에디터 + 데이터 저장 (Claude)

> "화면 하단에 텍스트 에디터 UI를 만들어 줘. 입력한 텍스트가 로컬 저장소에 저장되고,
> 앱을 다시 켜면 그대로 불러와지는 데이터 로직을 파일별로 나눠서 작성해 줘."

### 3단계 — 게임 시스템 연동 (Claude)

> "저장할 때마다 이전 글자 수와 비교해 새로 늘어난 글자 수만큼 마나와 경험치를 증가시켜 줘.
> 경험치가 차면 레벨이 오르고, 상태값들이 화면 상단에 실시간 표기되게 해 줘."
> (비주얼은 이 단계에서 신경 쓰지 않는다. 오직 '숫자'가 정확히 올라가는지만 검증)

### 4단계 — 에셋 생성 (Higgsfield)

- 6.3의 프롬프트 가이드로 진화 단계별 스프라이트·몬스터·아이콘을 시리즈로 생성.
- 투명 배경 PNG / 애니메이션 확보 후 `assets/` 폴더에 정리.

### 5단계 — 에셋 연동 & UI 폴리싱 (Claude + 에셋)

> "펫 이미지를 상태창 중앙에 띄우고 레벨에 따라 교체되는 로직을 추가해 줘. 전체 UI 테마를
> '1990년대 레트로 다마고치·고전 로그라이크' 스타일로: 배경 `#8BAC0F`, 텍스트 `#0F380F`,
> 픽셀 폰트 적용, 테두리는 각진 두꺼운 실선으로."

### 6단계 — 문서화 (Claude)

> "지금까지의 모든 폴더·파일의 역할, 사용 라이브러리, 주요 변수와 계산식을 `README.md`로 정리해 줘.

**→ 이 README가 장기 유지보수의 핵심 자산이다. 기능이 추가될 때마다 갱신을 요청한다.**

### 개발 실패를 막는 마인드셋

1. **한 번에 다 만들려고 하지 않는다.** 환생·진화·상점을 동시에 요구하면 AI도 코드를 엉키게 짠다.
2. **작게 쪼개서 질문한다.** "글자 치면 숫자가 오르는 메모장" → 동작 확인 → "키워드 보너스 추가" → 확인 → "상점 추가".
3. **에러가 나면 에러 메시지를 그대로 붙여넣고** 어디서 고장 났는지 AI에게 진단시킨다.
4. 각 Phase 완료 시점마다 **git 커밋으로 스냅샷**을 남겨, 언제든 되돌릴 수 있게 한다.

## 부록 B. 원안(Text Echo) 대비 변경 사항

| 항목 | 원안 | 본 기획서 |
